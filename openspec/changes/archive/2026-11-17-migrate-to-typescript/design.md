# Design

## Context

See proposal.md for why. The facts that shape the approach:

- 28 source files, about 3,600 lines. `components/Chime.jsx` (913) and `lib/engine.js` (937) are half of it. None of them carry JSDoc types today.
- `lib/engine.js` and `lib/share.js` have to import in plain Node: `scripts/catalog.mjs` imports the engine, and the engine checks in CLAUDE.md's Testing section run against it. Those two files import each other with explicit `.js` extensions (`./engine.js`). Everything else imports without extensions or through `@/`, which only Next resolves.
- Local Node is 26, where type stripping is on by default (since 22.18 / 23.6): `node file.ts` runs if the file uses only erasable syntax. `package.json` says `"node": ">=20"`.
- Relay compiles in two places that must agree: `relay.config.json` (the compiler, run by `scripts/relay.mjs` before `dev` and `build`) and `compiler.relay` in `next.config.mjs` (SWC rewrites `graphql` tags into imports of `__generated__/` files).
- Tone, motion, radix-ui, zod, lucide-react, class-variance-authority and Next ship their own types. React, React DOM, Node, react-relay and relay-runtime need `@types/*`.

## Goals / Non-Goals

**Goals:**
- Every file in `app/`, `components/`, `lib/` and `scripts/` is TypeScript under `strict`, with no `any` except at the edges where the input is raw bytes or untyped browser APIs, each with a comment.
- The behavior is the same, byte for byte where it can be measured: share links, MIDI bytes, `.mid` output, strike timing for a seed, SF2 parsing.
- The engine and share code still run in Node with no build step.

**Non-Goals:**
- Refactoring while converting. Function boundaries, names, file layout and the engine's section order stay as they are. A function that's awkward to type gets an explicit type, not a redesign.
- Adding a test runner. Vitest stays on the ideas list; this change uses one-off checks (see Migration Plan).
- Typing the dmbk GraphQL API beyond what Relay generates.
- Converting `postcss.config.mjs` (see Decisions).

## Decisions

**1. Node's built-in type stripping for Node-side code, not `tsx` or a build step.**
`lib/engine.ts`, `lib/share.ts` and `scripts/*.ts` run with plain `node`. To make that work, the tsconfig sets `erasableSyntaxOnly: true` (no enums, namespaces or parameter properties, which stripping can't handle) and `allowImportingTsExtensions: true`. Imports that Node follows use the `.ts` extension (`./engine.ts`, `../lib/engine.ts`). `engines.node` becomes `>=22.18`, the first LTS where stripping is on without a flag.
*Alternatives:* `tsx` adds a dependency and a wrapper to every script call. Compiling the scripts adds a build output to keep track of. Both work on older Node, but we don't need older Node.

**2. One strict tsconfig, no `allowJs` left at the end.**
`strict: true`, `noEmit: true`, `moduleResolution: "bundler"`, `jsx: "preserve"`, the `@/*` path alias moved over from `jsconfig.json`, and Next's plugin. `noUncheckedIndexedAccess` stays off: the raster, the SF2 walker and the sim index typed arrays and fixed-length tuples constantly, and the flag would mean hundreds of `!` with no real protection. `allowJs` is on while files are being converted and removed in the last step, so a leftover `.js` file breaks the build.

**3. Types come from the existing sources of truth.**
- The unit record is `z.infer<typeof UnitSchema>` (plus `id`), exported from `lib/share.ts`. `Chime.tsx` uses that type instead of declaring its own copy, so the schema and the type can't drift apart. The same goes for `CompositionSchema` and the packed unit.
- A chime's params (`P`), the voice table, the SF2 structures (preset, zone, region, sample header) and the object returned by `createChime` get named interfaces in `lib/engine.ts`, next to the code that builds them. `Chime` is an exported type: `ReturnType<typeof createChime>`.
- The MIDI status snapshot is an interface in `lib/midiout.ts`. The Web MIDI types come from TypeScript's DOM lib, so we don't hand-write them.
- Relay operation types are generated by the compiler (decision 4).

**4. Relay emits TypeScript.**
`language: "typescript"` in both `relay.config.json` and `next.config.ts`. `__generated__/*.graphql.ts` stay git-ignored. The persisted-operation ids are hashes of the operation text, which doesn't change, so `lib/server/persisted-operations.json` and the API route's allowlist stay the same. The tasks check this by diffing the map before and after.

**5. Config files.**
`next.config.mjs` becomes `next.config.ts`, which Next 15 supports. `postcss.config.mjs` stays: PostCSS loads its config through its own loader, and a TS config there is fragile for no gain. `components.json` gets `tsx: true`. Generated components are still restyled by hand afterward, as CLAUDE.md already says.

**6. Convert in dependency order, with `git mv`, one file per step.**
`git mv` and then edit, so `git log --follow` and blame keep their history. The order runs from leaves to the root: `lib/utils`, `lib/colors`, `lib/changelog` → `lib/engine` → `lib/share`, `lib/midiout`, `lib/relay/environment` → `components/ui/*` → `Compositions` → `Chime` → `app/*` → `scripts/*` → configs. Each step must pass `tsc --noEmit` before the next one starts.

**7. Untyped edges are narrowed once, where they enter.**
These are the places where data comes in untyped: `localStorage` and the URL fragment (already run through zod, so they come out typed), the Web Audio `setSinkId`/`sinkchange` extensions that TypeScript's DOM lib may lack (a small `declare global` augmentation in one file), `navigator.audioSession` (same), and the SF2 `DataView` reads, which are typed as numbers. No `@ts-ignore`. A `@ts-expect-error` is allowed only with a comment saying why.

## Risks / Trade-offs

- [Vercel's Node version is below 22.18, so `pnpm relay` (now `node scripts/relay.ts`) fails the deploy] → Check the project's Node setting before merging. Vercel's default is 24, which is fine. Set `engines.node` so Vercel picks a version that supports stripping.
- [`@types/react-relay` and `@types/relay-runtime` lag behind Relay 21 (DefinitelyTyped)] → Pin the newest versions and check that the hooks we use (`useLazyLoadQuery`, `usePaginationFragment`, `useMutation`, the `updater` store API) type-check. If one doesn't, add a narrow local declaration rather than `any` across the whole file.
- [A conversion that looks harmless changes behavior, for example `x | 0` becoming `Math.trunc`, or a default argument moving] → Stick to Non-Goals: no rewrites. Before converting, capture golden outputs from the JS version and compare them afterward (Migration Plan).
- [Strict null checks in `Chime.tsx` push toward adding defensive checks that change render timing (refs, `outChannels` before audio starts)] → Use non-null assertions (`!`) only where the current code already relies on the value being set, and leave the control flow as it is.
- [SSR mismatch: typing doesn't catch reading a browser API during render] → No change in risk. The existing rule ("hold it in state set in a mount effect") still applies, and the Playwright check runs on the production build.
- Trade-off: stripping means no `enum` or parameter properties anywhere. The code has none today, and string unions cover the same cases (`"chime" | "furin"`, `"poly" | "mono"`).

## Migration Plan

1. **Before any rename,** record golden outputs from the JS code into the scratchpad, not the repo: `encode()` of a few fixed compositions (1 unit, 16 units, a furin, edge roots); `buildMidi(renderTake(60))` bytes for seed 12345 with GM tubular bells and a built-in voice; strike count and the first 50 strike times for seed 12345 at WIND 0.45 for 2, 6 and 8 tubes and for a furin; `pnpm catalog` output; `lib/server/persisted-operations.json`.
2. Convert in the order of decision 6, running `tsc --noEmit` after each file.
3. After the last file: remove `allowJs`, run `pnpm build`, and compare every golden output with the TypeScript version (they must be identical). Then run a Playwright pass on `pnpm start`: load the page, strike, open SETTINGS, change SCALE and SOUNDFONT, COPY, SHARE and reopen the link, fake MIDI bytes, and the COMPOSITIONS panel with a stubbed `/api/graphql`.
4. Update CLAUDE.md, AGENTS.md and the README: TypeScript by default, `.ts`/`.tsx` paths, `pnpm typecheck`, and engine tests run with `node` on `.ts` files. Remove the note about the module-type warning if Node no longer prints it.
5. Ship as one PR. Rollback is reverting the merge. No data, link or API format changes, so nothing stored has to be migrated back.
