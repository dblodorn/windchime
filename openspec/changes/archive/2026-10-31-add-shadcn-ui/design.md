# Design

## Context

See proposal.md for the motivation, and `specs/ui-controls/spec.md` for the required look and behavior. The `midi-output` spec is unchanged and has to keep passing.

The current state that shapes this design:

- **Styles:** `app/globals.css` is 56 lines of hand-written CSS with two tokens, `--paper` and `--ink`. It contains browser-specific slider and checkbox rules and element selectors (`button`, `.param select`, `input[type=range]`).
- **Font:** `app/layout.jsx` loads Courier Prime with next/font as CSS variable **`--font-mono`**. Tailwind v4 already defines a theme variable named `--font-mono`, so the two would collide (see Decision 3).
- **`Chime.jsx` controls:** 5 native `<select>`s and 4 `<input type="range">`s, all with `onChange`. There are 3 checkboxes wrapped in `<label>`, and about 10 `<button>`s, two of them toggles using `aria-pressed`.
  - SCALE uses `<optgroup>`. SOUNDFONT has roughly 16 groups and 180+ options once the GM font loads.
  - MIDI OUT uses `value=""` for NONE and `"wanted"` for a disabled "NAME DISCONNECTED" option.
- **`Param`** renders `<label htmlFor={id}>` with three spans: the key, the dotted leader, and the value.
- **Toolchain:** plain JS. `jsconfig.json` has only `baseUrl`. The package manager is pnpm with a frozen lockfile on Vercel.
- **Versions on npm today:** `shadcn` 4.23.0, `tailwindcss` 4.3.3, `radix-ui` 1.8.1 (the unified package the current CLI emits).

## Goals / Non-Goals

**Goals:**
- Add shadcn components as owned source under `components/ui/`, generated by the CLI and then edited to the 1-bit theme, so that later `shadcn add` calls start from the same tokens.
- Make the theme tokens the single source of the two colors. No component should hard-code `#000` or `#fff`.
- Keep `Chime.jsx`'s state, effects and engine/MIDI wiring as they are. Only the markup and the event adapters change.

**Non-Goals:**
- No TypeScript.
- No dark mode, no new colors, and no shadcn components beyond Button, Select, Slider and Checkbox.
- No change to the canvas, the tube readout grid, the engine, `lib/midiout.js`, audio, or `.mid` export.
- No Vitest. The Playwright scripts stay uncommitted scratch scripts, as in the last change.

## Decisions

### 1. Generate with the shadcn CLI, then hand-edit
1. Add the `@/*` alias to `jsconfig.json` first; CLI 4.23 refuses to init without it.
2. Run `pnpm dlx shadcn@4.23.0 init -b radix -p nova -t next --no-monorepo`. This writes `components.json` with `style: "radix-nova"`, `tsx: false` and `rsc: true`, with aliases `@/components`, `@/components/ui` and `@/lib/utils`.
3. Run `shadcn add button select slider checkbox`.
4. Edit the generated files for the theme.

What CLI 4.23 actually produces, compared with what was assumed before implementing:
- `lib/utils.js` re-exports `cn` from shadcn's own `cn` package (a compiled `clsx` + `tailwind-merge`) instead of depending on both.
- `globals.css` imports `tw-animate-css` and `shadcn/tailwind.css`. The latter defines the `data-open`/`data-checked`/… variants the components use, so both packages are kept as devDependencies; they are only read at CSS build time.
- `init` swaps the font to Geist in `layout.jsx`; that change is reverted.

*Alternative: hand-write the components.* Rejected. Generating from the CLI keeps the files in the form shadcn expects, so `shadcn add` and `diff` keep working later, and it avoids copying by hand from documentation that changes.

### 2. Theme: every shadcn token is black or white
`globals.css` defines `:root` tokens as hex values with no `.dark` block:
- `--background`, `--card`, `--popover`, `--primary-foreground`, `--secondary`, `--muted`, `--accent-foreground` and `--input` are `#ffffff`.
- `--foreground`, `--card-foreground`, `--popover-foreground`, `--primary`, `--secondary-foreground`, `--muted-foreground`, `--accent`, `--border` and `--ring` are `#000000`.
- `--destructive` is `#000000`.
- `--radius` is `0rem`.

`@theme inline` maps these to Tailwind colors (`--color-background: var(--background)` and so on). It also sets every `--radius-*` to `0` and every `--shadow-*`/`--inset-shadow-*`/`--drop-shadow-*` to `none`, so a `rounded-md` or `shadow-xs` left in generated code does nothing. Then `color-scheme: light`, and the CLI's `@custom-variant dark` line is deleted, so `dark:` classes never match.

`--accent` is **black**. shadcn uses `accent` for the hovered or highlighted state of select items and buttons. Black with `--accent-foreground` white gives the existing inverted highlight with no changes to the components.

*Alternative: keep the CLI's oklch neutrals and override each component.* Rejected. The greys would show up in every component added later.

### 3. Rename the next/font variable to `--font-courier`
`layout.jsx` changes to `variable: "--font-courier"`. In `@theme inline`, `--font-sans` and `--font-mono` are both set to `var(--font-courier), "Courier Prime", "Courier New", Courier, monospace`. Body gets `font-sans`.

Keeping the name `--font-mono` would make `--font-mono: var(--font-mono)` refer to itself and resolve to nothing. Renaming the next/font variable is the only change needed outside CSS.

### 4. Component edits (in `components/ui/*.jsx`)
Remove from every component: `shadow-*`, `rounded-*`, every `dark:*` class, `ring-*`/`focus-visible:ring-*`, and `aria-invalid:*` ring styles. Every component gets the same focus treatment, a shared `focus-visible:outline-1 focus-visible:outline-dashed focus-visible:outline-foreground focus-visible:outline-offset-3`, which reproduces today's `:focus-visible` rule.

- **Button:** the `default` variant is `border border-foreground bg-background text-foreground hover:bg-foreground hover:text-background aria-pressed:bg-foreground aria-pressed:text-background uppercase tracking-[.06em]`. The size is one compact size matching `padding: 6px 10px`. Disabled is `disabled:opacity-40 disabled:pointer-events-none`, so it can't invert on hover. The other CLI variants are kept but unused. It still renders a native `<button>`, so `onClick` stays a direct user gesture for the iOS audio unlock.
- **Select:**
  - **Trigger:** full width, `border border-foreground`, compact padding, `mt-1`.
  - **Content:** `position="popper"`, `border border-foreground bg-background`, `w-(--radix-select-trigger-width)` with `max-w-[calc(100vw-32px)]`, and `max-h-(--radix-select-content-available-height)` with scrolling. This covers the spec's 375 px case.
  - **Items:** highlighted is `bg-accent text-accent-foreground`, and disabled is `opacity-40`.
  - **Groups:** `SelectGroup` with a `SelectLabel` heading in bold uppercase.
  - **Icons:** the chevron and check icons from `lucide-react` are replaced with text glyphs: `▾` on the trigger and `■` as the selected-item indicator. So there's no `lucide-react` dependency, and the icons can't pick up a stroke color outside the palette. If the CLI adds `lucide-react`, it's removed from `package.json`.
- **Slider:**
  - **Track:** `h-px bg-foreground`. The range fill is transparent, so the track reads as one line, as today.
  - **Thumb:** `block w-[9px] h-[17px] bg-foreground border-0 rounded-none`.
  - **Root:** `h-[22px] touch-none`.
  - The component accepts `aria-labelledby`/`aria-label` and passes them to the Thumb. The Thumb is the element with `role="slider"`, so a `<label htmlFor>` pointing at the Root would not name it.
- **Checkbox:** `size-[14px] border border-foreground bg-background`. The indicator renders a `size-[8px] bg-foreground` square, which keeps the 2px inset from today's `box-shadow` trick without using a shadow. No check icon.

### 5. `Chime.jsx` adapters
- **`Param`:** keeps its markup, with classes moved to utilities and the `.lead` dotted leader kept as a small component class. It gives the label span an id, `${id}-label`, so sliders can use `aria-labelledby`. Selects keep `htmlFor={id}` onto the trigger `<button id>`, which names a button.
- **Selects:** Radix Select values must be non-empty strings.
  - ROOT, SCALE and CHANNEL use `String(n)`, with `onValueChange={v => setX(+v)}`.
  - MIDI OUT uses the sentinel **`"none"`** in place of `""`. `choosePort(v === "none" ? "" : v)`, and `"wanted"` stays a disabled item.
  - SOUNDFONT keeps its `s<font>:<preset>` and `v<i>` ids.
- **Sliders:** `value={[x]}`, `onValueChange={([v]) => setX(v)}`, with the same `min`, `max` and `step`. `onValueChange` fires during drags, which keeps the "live filter and CC74 while dragging" requirement without extra code.
- **Checkboxes:** `checked={x}` and `onCheckedChange={v => setX(v === true)}`, inside the existing `<label>`, which Radix supports for clicking the label to toggle.
- **SOUNDFONT size:** about 180 items, rendered only while open. Radix Select doesn't virtualize, which is acceptable at this size. Typing to jump comes built in.

### 6. What stays in `globals.css`
Tokens, `@theme inline` and the base layer (`html`/`body` background and color, font, line height, safe-area padding). Small component rules that utilities can't express cleanly are also kept:
- canvas pixelation (`image-rendering: pixelated/crisp-edges`);
- `.lead` (a dotted bottom border shifted up 4px);
- `.tubes .hit`, which the strike handler toggles by class name;
- the reduced-motion rule.

Everything else (main grid, sticky stage, `.sheet`, `.params`, `.status`, `.note`, `.sfrow`, `.checks`) becomes utility classes in `Chime.jsx`. Tailwind's Preflight replaces the hand reset. The `h1` size and letter-spacing move to utilities on the element.

### 8. Found during implementation
- **Page padding lives on `html`, not `body`.** While a Radix Select is open, its scroll lock injects an unlayered `body { padding-left: 0; … }`, which shifted the whole page 16 px. `html` padding isn't touched.
- **Server render:** Radix fills `SelectValue` only on the client, and renders slider thumbs hidden until it can find their index in the DOM. So `ParamSelect` passes the current choice's text as `SelectValue` children, and `Slider` draws an `aria-hidden` stand-in thumb until mount at Radix's in-bounds position, `left: calc(p% + 4.5px·(1 − p/50))`. With JavaScript off, it is within 0.6 px of the hydrated thumb.
- **`Param` renders a `<div>`, not a `<label>`.** A `<label htmlFor>` pointing at a select trigger (a button) opens the list when the row is clicked, and names the control with its value text too ("ROOT C5"). Controls are named with `aria-labelledby="${id}-label"` instead.
- **Checkbox has `p-0`**, so it never inherits button padding.

### 7. Tests
**MIDI script** (`midi-check.mjs`): the helpers move from `selectOption`, the value setter and `getByLabel`-on-input to roles:
- `pickOption(name, optionText)`: click the combobox by name, then click the option by role and name.
- `setSlider(name, value)`: focus the slider, press Home, then step with the arrow keys or Page keys, computed from `step`.
- Checkboxes via `getByRole("checkbox", { name })`.

All 49 checks must pass unchanged in intent.

**New `ui-check.mjs`:**
- Sweep computed styles across all elements and control states (rest, hover, focus, open, disabled) for the palette, `border-radius` and `box-shadow`.
- Font family, roles and names, and slider `aria-valuemin`/`valuemax`/`valuenow`.
- Keyboard flows from the spec scenarios.
- Hydration warnings in the console.
- At 375 px: select lists fit and scroll, and the page has no horizontal scroll.

## Risks / Trade-offs

- **[Radix Select on iOS doesn't use the native wheel picker]** → The spec asks for an accessible, scrollable list that fits the screen instead. This is checked by hand on an iPhone during the preview step.
- **[The SOUNDFONT list of about 180 items has no virtualization]** → Opening it renders about 200 nodes, which is fine. If more fonts are loaded later (several SF2s), this is the first thing to revisit.
- **[CLI output drifts from what this design assumes]** (for example the class names it generates, or `radix-ui` vs `@radix-ui/*`) → The CLI version is pinned at 4.23.0. The token-level overrides (radius and shadow set to zero, accent set to black) neutralize most drift. The style sweep in `ui-check.mjs` catches whatever slips through.
- **[Tailwind Preflight changes element defaults]**, such as heading margins, `img`/`canvas` display, and button cursor → Every element on the page is restyled explicitly, and the canvas keeps its own rule. Compare screenshots before and after at desktop and phone widths.
- **[Bundle size grows]** with Radix Select, Slider, Checkbox and `cn` → Measured: 115 kB → 165 kB (+50 kB), mostly Select. It was reviewed and accepted: a 6 MB SoundFont already loads with the page, and the styled, keyboard-accessible select is the point of the change.
- **[Focus: Radix Select returns focus to the trigger on close]** → That's the expected behavior and matches the spec's keyboard flow. The dashed outline shows only with `:focus-visible`.

## Migration Plan

- Work on a branch. The Vercel preview lets you check on a real phone, especially iOS Select and Slider touch, before merging to `main`.
- `pnpm-lock.yaml` must be updated in the same commit, because Vercel uses a frozen install.
- No data or `localStorage` changes.
- Rollback: revert the merge commit. There's no persistent state to undo.

## Open Questions

- Glyph choice for the select chevron (`▾`, `▼` or `v`) and the selected-item marker. This is cosmetic, can be settled while restyling, and doesn't affect the spec or the tasks.
