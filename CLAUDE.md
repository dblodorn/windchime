# Chime (windchime)

A wind chime simulation with 2–8 tubes (TUBES, 6 by default). Wind pushes a sail, the sail swings a disc clapper, and every strike on a tube is a note. Each unit can instead be a furin bell (INSTRUMENT): one bell, one note (ROOT), its clapper swung by a paper strip in the wind. It plays in the browser (Tone.js + an SF2 sampler) and sends live MIDI to hardware (Web MIDI). SHARE copies a link that carries the whole composition, and MENU opens COMPOSITIONS, a public list of compositions anyone can save anonymously and load (stored by the dmbk GraphQL API). The page holds 1–16 chime units (CHIME 1, CHIME 2, …): COPY on a unit makes another with its state, each unit has its own settings, sound, MIDI channel and audio OUTPUT, and all of them share the MIDI port and the audio device. AUDIO picks the output device (any device the OS exposes, such as a USB class-compliant multichannel interface), and each unit's OUTPUT sends it to a channel pair or a single channel of that device. The page title is "Chime"; there is no on-page heading and no AUDIO or MIDI status line. The engine can still record takes and build `.mid` files (sections 8 and 10), but the UI no longer exposes REC, RENDER or SAVE MIDI, and it has no .sf2 upload: the SOUND select offers the built-in synth voices, the external synths (the Casio VZ-10M emulator, `@dblodorn/casio-vz-engine`, with a PATCH picker of the voices shared from the VZ-10M editor) and the bundled GM font.

- Live: https://chime.dmbk.io (Vercel project `windchime`, team `db13`; also served at https://windchime-lyart.vercel.app). DNS for dmbk.io is on DigitalOcean: `chime` is a CNAME to the Vercel project target `34679086444df785.vercel-dns-016.com`.
- Repo: https://github.com/dblodorn/windchime. Every push to `main` deploys to production.

## Stack

- Next.js 15 App Router, React 19, TypeScript (`strict`, `tsconfig.json`). TypeScript is the default for every new file; no `.js`/`.jsx` except `postcss.config.mjs`. TypeScript is pinned to 6.0: TypeScript 7 (the native compiler) has no JS API, which `next build`'s type check needs.

Node runs `lib/engine.ts`, `lib/share.ts` and `scripts/*.ts` directly with its built-in type stripping (Node ≥ 22.18; local and Vercel are 26), so that code uses only erasable syntax (`erasableSyntaxOnly`: no `enum`, `namespace` or parameter properties) and imports what Node follows with the `.ts` extension (`./engine.ts`). Browser APIs the DOM lib lacks (`AudioContext.setSinkId`/`sinkId`, `navigator.audioSession`, `MediaDevices.selectAudioOutput`) are declared, all optional, in `lib/web-audio.d.ts`. No `any` or `@ts-ignore`; a cast only where outside data comes in, with a comment.
- `tone` (Tone.js 15) for the audio graph.
- `motion` (pinned 14.3.0, `motion/react`) for dragging the units.
- `zod` 4 for the unit record schema (stored data, share links and saved compositions), in `lib/share.ts`.
- `@dblodorn/casio-vz-engine` (pinned exactly, from GitHub Packages) for the VZ-10M: the emulator as an AudioWorklet, loaded with a dynamic `import()` from `lib/synths.ts`, so its own 36 KB chunk downloads only when a unit sounds with it. Installing needs a token: the committed `.npmrc` holds only `@dblodorn:registry=https://npm.pkg.github.com`, because pnpm 12 won't expand `${…}` in auth set in a repository's `.npmrc`. ### lib/engine.ts sections, in order

1. **Raster**: 200×200 1-bit scratch buffer (`px`, `line`, `present(ch)`), shared: each chime draws into it in turn and presents it to its own canvas in that chime's ink (`setInk(hex)`, its MIDI channel's color; black by default) on white. The figure is still computed in the original 192×232 three-quarter projection and mapped onto the paper by one scale, `toX/toY` with `K = 0.8, TOP = 0`. `seg()` draws a line through that transform, and `outline(cx, cy, rx, ry, n)` is a closed ellipse made of `n` straight `seg`s. K was set from measured extents: the figure fits at rest and in about 99% of frames at WIND 0.45. Stronger gusts clip at the paper edge, by choice; never limit the sim to avoid it.
2. **Pitch and scales**: `noteName`, `mtof`, `cutoffHz(x) = 60·2^(8x)` (slider 0..1 → 60 Hz–15 kHz), `SCALES` (grouped; 32 scales, Ryukyu first, Korea second), `SCALE_LIST`, `tubeNotes(deg, n)` (the first n notes, wrapping around an octave up when the scale is shorter).
3. **Params**: `defaultParams()`: each chime has its own `P` (volume, tubes, wind, decay, cutX, cutoff, q, root, scale, output), changed through its `setParams`. A chime's `noteOf(i) = foldNote(P.root + P.scale[i])` (read modulo the scale's length as a backstop). `P.root` is a MIDI note from 0 to 119 (C-1–B8); `foldNote` lowers a note above 127 by octaves until it fits (B8 plus QUARTAL on 8 tubes reaches 144), so sound, MIDI and recordings stay in range. The tube readout and TEST NOTE use the same `foldNote`; `tubeLen` (the drawing) uses the unfolded offsets, so folded tubes aren't drawn longer. The UI sends `tubes` and the matching `scale` (`tubeNotes(deg, tubes)`) in one `setParams` call.
4. **Geometry + simulation**: `makeSim(seed, n = 6)` and `step(sim, P, dt, onHit)` at a fixed 240 Hz. `step` runs `stepWind` (the wind force `F`, shared by both instruments; its random draws keep their old order, so a tube chime's strikes for a seed are unchanged by the furin) and then `stepTubes` or `stepFurin` by `P.instrument`. Each sim carries its tube layout, `sim.lay = layout(n)`: tube i hangs at `start(n) + i·2π/n` on the ring, where `START` gives each count's start angle (2 → −20°, 3 → −50°, 4 → −38.5°, 5 → −74°, 7 → −58.5°, 8 → −73°), chosen to spread the tubes widest on screen through the YAW view (narrowest gap ≥ 8.9 raster px); 6 keeps the original `−π/2 + π/6`, so its strikes for a given seed are unchanged. `setParams({ tubes })` (clamped to `MIN_TUBES`–`MAX_TUBES`, 2–8) calls `resize`: tubes 1…min(old, new) keep their motion, new ones start at rest, every tube gets one 80 ms cooldown (so a tube moved onto the clapper doesn't strike), and the wind, clapper, sail and random stream carry on. Wind is an Ornstein–Uhlenbeck force with `sqrt(P.wind)` scaling; the clapper is a damped spring; the tubes have their own springs; strikes are impulse collisions with restitution. Velocity is `24 + 1.1·|vr|` (clamped 1..127), with an 80 ms per-tube cooldown. The constants were tuned by measuring strikes per minute (≈1 at wind 0.1, ≈17 at 0.2, ≈57 at 0.45, ≈80 at 0.8, with 6 tubes). Re-measure if you change them. The rate follows the tube count on purpose (seed 12345, WIND 0.45, 5 min): about 29/min at 2 tubes, 34 at 3, 47 at 4, 64 at 5, 67 at 6, 75 at 7 and 92 at 8.
   - **Furin** (`P.instrument === "furin"`): the bell is rigid on its hook; `sim.fu` holds the clapper `c` and the paper strip `q`, two coupled masses in the horizontal plane. The wind drives only the strip, the strip drags the clapper (that lag is the furin's uneven rhythm), and a strike fires where the clapper meets the bell's wall (`FRC`, the wall radius at `CLAP_Y` minus the clapper's), with restitution `FE`. A strike disarms the clapper until it is 1.5 units back off the wall, with a 40 ms minimum gap, so a clapper pressed to the wall doesn't strike every step. Velocity is `12 + 115·(1 − e^(−vr/45))` (a soft curve: hard swings still differ, almost none reach 127). Constants `FA`…`FGAP` were tuned by measuring (5 min, 4 seeds): about 0.3 strikes/min at WIND 0.1, 9 at 0.2, 36 at 0.45, 53 at 0.8; at 0.45 velocities run about 20–122 (10th–90th percentile 48–103) and mean velocity rises with WIND; no strikes in still air; the figure never clipped in 10 min at 0.45. Re-measure if you change them. `setParams({ instrument })` → `switchInstrument`: the incoming instrument starts at rest (a fresh `sim.fu`, or rest tubes with one 80 ms cooldown and the clapper `s` at rest); the wind and `t` carry on. A furin's `noteOf(i)` is `P.root` (`noteAt`); it keeps TUBES and the scale in `P`, unused.
5. **Drawing** (*Design By Numbers* style): single-pixel lines only, no fills, so it's a wireframe with no depth sort.
   - Order: wind dashes, hook, ring `outline` (24 segments), tubes, clapper `outline` (16) and sail rectangle.
   - Tubes: `tubeGeom(P, lay, i, tb)` gives each tube's string attach point, top and bottom; `drawTube` draws the string and an outlined body ±`RT` wide.
   - Camera: every drawn sim position goes through `view(x, z)`, a `YAW = 20°` turn about the vertical axis. Without it, the 6-tube layout's tubes 1/3 and 4/6 share a screen x and merge. The sim itself is not rotated.
   - Wind: each chime's `streaks` (`makeStreaks()`) are solid dashes in projection space, wrapping at the paper edges `OX0`/`OX1`.
   - Furin (`drawFurin`): hook, crown `outline`, the dome's two silhouette edges (8 `seg`s each of `bellR(y)`), the rim `outline` at `BELL_RIM`, the clapper on a string from the crown, and the strip (a rectangle narrowing with the wind angle, like the sail) on a string below the clapper. The bell is axisymmetric, so YAW only moves the clapper and strip. `bellOutline()` gives its silhouette rows on the paper (for tests).
6. **Audio**: per chime, voices → its native input GainNode (target = VOLUME while its SOUND is on, else 0, ramped about 40 ms by `level`) → its `Tone.Filter` low-pass (FREQUENCY = cutoff, RESONANCE = Q, −12 dB/oct) → its router (`route`) → the bus of its channel pair → one `ChannelMerger(N)` → the destination, set to N channels, `explicit`, `discrete` (built by `setupOutput` on the first `startAudio()`; `master` is the merger, only a "started" marker now).
   - **Own context:** `startAudio()` makes the native `AudioContext` itself and hands it to Tone (`Tone.setContext(new Tone.Context(ctx))`), because `setSinkId` lives on the native context. It passes `sinkId` to the constructor only when the UI says the device is listed (`setAudioDevice(id, { listed })`): Chrome breaks the context ("encountered an error from the audio device") on an unknown id instead of throwing. Otherwise it switches with `setSinkId` right after, which fails cleanly.
   - **Buses:** one per pair k (channels 2k+1, 2k+2), made on first use: native `DynamicsCompressor` (threshold −16, ratio 4, attack 3 ms, release 250 ms, knee 30 = the old `Tone.Compressor`) → Gain 0.85 → `ChannelSplitter(2)` → merger inputs 2k, 2k+1. Per pair because a compressor holds at most 2 channels and a shared detector would duck one output when another hits. With N = 2 the output is bit-identical to the old single chain (rendered and compared). N is `maxChannelCount`, capped at 32 (`MAX_OUT`); a device change (`setSinkId`, `sinkchange`) rebuilds the merger and re-routes every chime (`refreshOutput`).
   - **Routing:** a chime's `P.output` is `{ first, count }` (`outputOf("3-4")` → `{ first: 2, count: 2 }`). A pair connects the filter straight to its bus; one channel goes through a mono GainNode (`channelCount 1`, `speakers` fold) into one input of a per-chime `ChannelMerger(2)` and then that pair's bus. Units on the same or overlapping outputs are summed there and share that bus's compressor. When the device lacks a chime's channels it is routed to 1–2 (`outputAvailable()` false) and goes back when they return. Changing OUTPUT reconnects only the router, so ringing notes move without being cut. `onOutputChange(fn)` fires with N when audio starts and whenever N changes; `outputChannels()` is null before audio starts; `audioOutSupported()` is `"setSinkId" in AudioContext.prototype` (Chromium only).
   - **External synths:** a chime on `x:<synth>` (`ch.ext`) gets its own engine instance (`ensureSynth`: the registry's `engine()` import, `createSynth(actx)`, output → the chime's input GainNode, so VOLUME, filter and OUTPUT apply) on SOUND on or on choosing it while sounding; a failed load is forgotten and retried. `playExternal` sends `noteOff` then `noteOn` (a re-strike restarts) and a per-note timer sends `noteOff` after DECAY. Until the instance is ready it plays `VOICES[0]` through `playVoice`, like `playSF` before its samples. `setPatch(bytes | null)` loads the patch (null or a bad patch → the synth's INIT); notes already sounding keep theirs. SOUND off ends its notes (`allNotesOff`); a voice change away and `destroy()` dispose the instance. Measured: 16 VZ units at WIND 0.8 cost about 2.5% of a core over 16 default-voice units (headless Chromium, M4 Pro).
   - **Voices:** a chime's graph (`buildGraph`) is made when its SOUND first turns on; its FM `PolySynth` only when it plays FM CRYSTAL. `ring(ch, …)` schedules nothing for a silent chime (SOUND off, VOLUME 0, or `setMuted`). Built-in `VOICES` are additive partials (tubular bells 1/2.756/5.404/8.933, etc.) or the FM synth, each mapped to a GM program for MIDI. `VOICES[6]` is FURIN (bell-plate partials 1/2.405/4.12/5.94/8.47, an octave up, with the chorus beat; GM Tinkle Bell, 112), appended at the end like everything indexed. `setMuted` silences every chime's browser sound only.
7. **SF2 sampler**: `parseSF2` (RIFF walk, phdr/pbag/pgen/inst/ibag/igen/shdr), `resolvePreset` (merges global and local zones; key/vel ranges, root override, coarse/fine tune, attenuation, pan, loop mode), `sampleBuffer` (lazy Int16 → AudioBuffer, cached per font), `playSF`. SF2 volume envelopes are ignored on purpose: DECAY sets every note's length. Attenuation uses the EMU/FluidSynth 0.4 factor.
   - **Loading in pieces**: `loadFont(url, name, { signal })` allocates one buffer of the file's full size and fills it with ranged fetches, so `parseSF2` and `sampleBuffer` read their usual offsets. On load it fetches `bytes=0-4095` (total size from `Content-Range`, RIFF walk to the `pdta` list) and then `pdta` to the end: 2 requests, about 209 KB of the 6 MB. Samples come later through `loadSamples(regions)`: it skips samples in `f.loaded` or `f.pending`, merges byte ranges closer than 16 KB into one request (Tubular Bells is 1 request of 71 KB, the Standard drum kit 3, no preset more than 7), and forgets a failed download so the next call retries; it never rejects. A `200` answer (a server ignoring Range) is the whole file: `f.all` is set and nothing more is fetched. `addFont(arrayBuffer)` (Node, tests) also sets `f.all`.
   - **When samples load**: only `setSound(true)` and `chooseVoice` on a sounding chime call `loadSamples`, so a muted unit, or MIDI-only use, downloads no samples. Until a note's samples are in, `playSF` plays that note with `VOICES[0]` (built-in tubular bells) through `playVoice`, the built-in path factored out of `ring`, into the same input (VOLUME and filter apply). The check is per note.
8. **Chimes**: `createChime({ seed })` returns one chime: `P`, `noteOf`, `setParams`, `chooseVoice` (returns false and keeps the voice for an unknown preset or synth), `setPatch`, `midiProgram` (null for an external synth: no GM program, so no program change; takes use program 1 under the synth's name), `setSound(on, { quiet })` (needs `startAudio()` first; plays a short arpeggio on tubes 1, 3 and 5, clamped to the last tube, unless `quiet`), `onHit(fn)` (listeners get `(tubeIndex, velocity)`), `attach`, `tubeSegments`, `strikeAt`, `strikeTube`, `startRec`/`stopRec`/`recording`, `renderTake(sec)` (offline sim with a fresh seed, the chime's tube count and 2 s settle) and `destroy()`. On a furin, `strikeAt` hits inside the bell's silhouette padded 6 px (returns 0, else −1), `tubeSegments()` is `[]`, `strikeTube(0)` kicks the clapper off the wall (and blocks a follow-on strike for 250 ms), and SOUND on plays one strike instead of the arpeggio.
9. **Loop**: a chime's `attach(canvas)` adds it to the `live` set; one shared requestAnimationFrame `tick` steps each live chime at 240 Hz (its own accumulator), moves its streaks and draws it, and stops when the set is empty. `attach` returns the detach. `strikeAt(x, y)` takes paper pixel coordinates (0–200). It strikes the nearest tube within 6 px of its centerline and its height ±6 and returns its index (−1 for empty paper), through `strikeTube(i)`, which the readout's note pads call directly. `tubeSegments()` returns each tube's centerline on the paper (handy for tests). The canvas is `box-content` with a 1px border outside the drawing, so `ChimeUnit` subtracts the 2 px border from the available width, sizes the drawing area to whole multiples of 200 where it fits (capped at 298 px while `matchMedia("(width < 40rem)")` matches, the same query as Tailwind's `max-sm:`, so a unit is 300 px wide on phones and narrow windows; the `motion.section` carries `max-sm:w-[min(300px,100%)]` to match), sets the readout width to canvas + 2, and maps taps through `clientLeft`/`clientWidth`.
10. **MIDI file**: `buildMidi(take)` → format 0, 480 PPQ, 120 BPM; bank select + program; CC74/CC71 from the take's `cc` list; note-offs after DECAY (cut short by a re-strike of the same note). Drum kits (bank 128) go on channel 10.

### Voice ids

A chime's `chooseVoice(value)`: `"v<i>"` is a built-in voice, `"s<font>:<preset>"` is a preset in `fonts[font]`, `"x:<synth>"` is an external synth from `lib/synths.ts`. A synth's id is its engine package name without `@dblodorn/` and `-engine` (`@dblodorn/casio-vz-engine` → `casio-vz`), the vz10m repo's engine-package convention. A unit on an external synth also has `patch`: null for the synth's bundled INIT, or the 24-hex `_id` of a patch in its dmbk library (a `VzVoice` for `casio-vz`). That pair (`voice`, `patch`) is the only form a patch takes, in storage, links and saves alike, for every synth: a later emulator adds a registry entry (id, name, INIT, its library's GraphQL type, which must implement `SynthPatch`, and its list query in `PatchSelect.tsx`), never a new storage shape. Every other unit's `patch` is null (the schema forces it), and an `x:` id the registry doesn't know becomes `null`. The bundled GM font is the only font the UI loads (there is no .sf2 upload), so every `s` id is `s0:<preset>`. A unit's stored `voice` is `null` for the default: GM tubular bells once the font's tables have loaded (its samples load when the unit's SOUND goes on), the built-in tubular bells before. A stored `s` id the font doesn't have goes back to `null` when the font loads. `addFont` still `unshift`s a GM font to index 0, so if uploads ever come back, existing `s` ids need remapping by +1 when the GM font arrives.

## Constraints and decisions to keep

- **Changelog**: every change that ships a feature, bug fix or enhancement adds one entry to the top of `lib/changelog.ts` in the same change: the ship date, FEATURE, FIX or ENHANCEMENT, and one short line about what a player sees, hears or can do (not how it was built). Spec archiving, agent notes and tooling get no entry. `/changelog` must not import `components/ui/button` (it pulls radix-ui into the page's client JS); its BACK link writes out the button classes. Entries are separated by dashed rules.
- **Visual language**: one ink on white. The ink is pure black everywhere except inside a chime unit, which draws in its MIDI channel's ink. Pixelated canvas scaled by whole multiples, Knif Mono for every label. Parameter rows are `LABEL ....... value` with dotted leaders. No rounded corners, no shadows.
  - **Channel inks** (`lib/colors.ts`, like patch-cable colors): channel 1 is black, 2–16 are Sanzo Wada colors from https://sanzo-wada.dmbk.io (slugs kept in `CHANNEL_INKS`), each ≥ 3:1 against white and ≥ 14.6 CIEDE2000 from every other, chosen as primaries first (CARMINE, BLUE, KHAKI, DIAMINE GREEN, ORANGE…). The ink is derived from `channel`, never stored, so links, saves and the API don't change. `ChimeUnit` spreads `C.inkStyle(hex)` on its `motion.section`; it redefines every black theme token (`--foreground`, `--border`, `--accent`, …) plus `color`, so the drawing's border, round buttons, drawer, flash, leaders and focus outline all follow. `inkStyle` is `undefined` for black, so a channel 1 unit is unchanged. **Popups portal out of the unit** and don't inherit it: `PopoverContent` gets `style={ink}`, `ParamSelect` reads `InkContext` (provided inside the popover) for its `SelectContent`, and `SearchSelect` takes `contentStyle`. Anything new that portals out of a unit must carry the ink too, or it draws black. The page's own controls (button row, MENU, COMPOSITIONS, MIDI/AUDIO dialogs) stay black. The filled-color exceptions outside the units are the MIDI OUT legend's swatches, the active-channels strip's squares (see **Channel focus**) and the changelog's type badges (`TYPES` in `lib/changelog.ts`: FEATURE Dusky Green, ENHANCEMENT Dark Slate Purple, FIX Carmine, Sanzo Wada combination 225, each ≥ 5.3:1 against their white text).

The browser posts only `{ id, variables }` to `app/api/graphql/route.ts`, which accepts same-origin POSTs (`Sec-Fetch-Site`, else `Origin` vs `Host`) for ids in the persisted map, and forwards them to `DMBK_GRAPHQL_API_URL` (default `https://graphql.dmbk.network/graphql`) with `x-api-key: DMBK_GRAPHQL_API_KEY` and `x-end-user-ip` (first `x-forwarded-for` entry; the API's per-visitor save limit), nothing else. The key is set in Vercel (Production and Preview); without it saves fail with FORBIDDEN, and in production the route throws. Locally, set both in `.env.local` (git-ignored) to save; reads work keyless. Each unit carries `instrument` (`CHIME`/`FURIN`, enum `ChimeInstrument`; optional on input, and saves made before it come back as `CHIME`), so `fromSaved` reads a missing one as CHIME. An external synth's unit carries `voice: "x:<synth>"` and `patch` (24-hex id or null); `toSaved` sends `patch` only on those units, so a composition without external synths is sent exactly as before (pinned and compared), and `fromSaved` reads a missing `patch` as null and an `x:` voice it doesn't know as the default voice. The API keeps fingerprints unchanged by hashing `instrument` only for non-chime units and `patch` only for `x:` units; it refuses a `patch` on any other unit and doesn't check the patch exists. Patches are fetched through `SynthPatch` (`id name data`), an interface every synth library type implements (`VzVoice` now). Its `root` range (`INT_FIELDS.root` in its `src/lib/chime/shape.ts`, and the collection validator) is 0–119, the same as `UnitSchema`'s; widen both together.
- **MIDI port lifecycle** lives in `lib/midiout.ts`, not React. `wanted` is the chosen (or remembered, `windchime.midiOutName`) port *name*; it survives unplugging. `adopt()` runs after `connect()` and on every `statechange`: it selects the connected port named `wanted`, or on connect the only port there is. `setLive(port)` is the only writer of `output`; it calls `port.open()` and bumps `linkSeq`. On disconnect the note-off timers are dropped without sending. Every message takes its channel (1–16) first: `note(ch, n, vel, s, src, mono)`, `testNote(ch, n)`, `program(ch, bank, prog)`, `cc(ch, num, v)`; note-off timers are keyed `channel:note`, one entry `{ timer, end, srcs }` per sounding key. `src` is the striking tube (`${unitId}:${i}`), `mono` the unit's MIDI MODE. A strike on a sounding key from the same `src`, or any strike in MONO, sends the note-off first (one note per key); in POLY (default) a strike from another source stacks a second note-on and the key's single note-off moves out to the later end, so tubes or units sharing a pitch ring together. TEST NOTE passes no `src`, so test notes cut each other as before. `endNotes(ch)` ends one channel's notes (a unit changing channel or being removed; it also ends another unit's notes on the same channel). `allNotesOff(channels)` ends every note, then sends CC123/CC120 on each listed channel. `status()` returns one snapshot for the UI; each `ChimeUnit` keys its program-change/CC effects on `status().linkSeq` and its own voice, filter and channel, so a port that becomes live (chosen, auto-picked, replugged with the same id) gets the setup exactly once. A failed `requestMIDIAccess` is not cached, so CONNECT MIDI can be retried.
- **Strict mode** is on: effects run twice in dev. Engine listeners return unsubscribe functions; keep it that way.

## Commands

```bash
pnpm install
pnpm dev        # http://localhost:3000
pnpm build      # also type-checks
pnpm typecheck  # tsc --noEmit (needs next-env.d.ts, which dev and build write)
pnpm start      # serve the production build

pnpm schema:pull  # refresh schemas/dmbk-graphql-api.graphql from the API, then commit it
pnpm catalog    # print the scale/voice catalog for dmbk-graphql-api's catalog.json
```

There are no `lint` or `test` scripts; `pnpm typecheck` is the closest. `next-env.d.ts` and `*.tsbuildinfo` are git-ignored. The package manager is pnpm: `pnpm-lock.yaml` is committed and Vercel installs from it with a frozen lockfile, so update it (`pnpm install`) whenever `package.json` changes or the deploy fails. Don't add a `package-lock.json` alongside it.

## Testing

No automated tests yet. What has worked so far:

- **Engine in Node**: `lib/engine.ts` imports cleanly in Node (no DOM at top level). You can `addFont` the `.sf2` from `public/` (or test `loadFont`/`loadSamples` with a stubbed global `fetch` that honours `Range`), make a chime with `createChime({ seed })`, and call its `chooseVoice`, `setParams` and `renderTake(60)`, then `buildMidi`, without a browser. Smoke test: `node -e 'import("./lib/engine.ts").then(m => console.log(m.SCALE_LIST.length, typeof m.createChime))'` (prints `32 function`). Scripts that import the engine are TypeScript too and run with plain `node`.
- **UI in headless Chromium**: Playwright is fine for this. Stub `navigator.requestMIDIAccess` with fake outputs that record `send()` calls, and check the bytes (`0x9n`/`0x8n` on the chosen channel, `0xBn 74/71`, `0xBn 123` on PANIC). Drive controls by role and name (`getByRole("combobox" | "slider" | "checkbox", { name })`); native `selectOption` and input value setters no longer apply. Radix moves select focus on the next tick, so space keystrokes ~50 ms apart. SCALE, SOUND and PATCH are typed into (see **SCALE, SOUND and PATCH**). Don't run `next dev` while `next start` serves the same `.next` directory: dev overwrites the production build output.
- **COMPOSITIONS in Playwright**: intercept `**/api/graphql` with `context.route` and answer by operation name, looked up from `lib/server/persisted-operations.json` by the posted id. Find the panel by `getByRole("dialog", { name: "COMPOSITIONS" })`; while it is open the units are hidden from the accessibility tree, so check them by DOM (`section[aria-label='CHIME 1']`). The route itself is tested against `pnpm start` with `DMBK_GRAPHQL_API_URL` pointing at a stub server.
- **External synths in Playwright**: the VZ engine is an `AudioWorkletNode` named `casio-vz-engine`; wrap `window.AudioWorkletNode` in an init script to count instances, and count `createOscillator` calls to tell the built-in fallback from the engine. Set WIND to 0 before measuring a note's length, or the chime keeps striking itself. Answer `PatchSelectVzQuery` (`dmbkSoundVzVoices`) and `patchesQuery` (`node`, with `__typename` and `__isSynthPatch`) by operation name like COMPOSITIONS; node ids are base64 of `VzVoice:<24 hex>`. Playwright isn't a dependency: install it in a scratch folder.
- **Audio output in Playwright**: headless Chromium has one stereo device, so fake one in an init script: override `AudioDestinationNode.prototype.maxChannelCount` (and clamp its `channelCount` setter to the real max), stub `AudioContext.prototype.setSinkId` to change the fake count and dispatch `sinkchange`, wrap `AudioContext` to accept the `sinkId` constructor option, and replace `navigator.mediaDevices` with an `EventTarget` whose `enumerateDevices` and `getUserMedia` you control. To hear routing, wrap `AudioNode.prototype.connect` so the merger that feeds the destination also feeds a splitter and one `AnalyserNode` per channel, then read each channel's peak after a strike. Launch with `--mute-audio`. Stereo equivalence of a chain change: render both with an `OfflineAudioContext` and compare samples.
- Things only a person can check: real audio output, a real multichannel interface (device choice, separate outputs, unplug/replug), Safari and Firefox (no `setSinkId` on `AudioContext`: system output only; whether they expose more than 2 channels is unverified), iOS behavior, real MIDI hardware.

Good first additions would be Vitest unit tests for `parseSF2`/`resolvePreset`, `buildMidi` byte output, `tubeNotes`, the POLY/MONO `note()` rule, the share-link round trip (`encode`/`decode`, a pinned version 2 link, a version 1 link decoding to null), `toSaved` pinned for a composition without external synths, and strike-rate regression for the sim.

## Deploying

Pushing to `main` deploys production on Vercel (project `windchime`, team `db13`). Other branches get preview deployments behind Vercel login (standard deployment protection). Static files in `public/` are served as-is; `next.config.ts` sets long caching and an octet-stream type for `.sf2`. The soundfont is fetched with Range requests (Vercel and `next start` both answer `206`), cached `immutable`, and links store preset indices, so a different font must get a new filename, never replace `TimGM6mb.sf2` in place. `Chime`'s font effect aborts its downloads on `pagehide` and unmount and doesn't log the abort, so a reload during a download is not a console error.
